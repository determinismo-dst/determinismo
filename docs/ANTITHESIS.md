# Antithesis parity map

determinismo follows the Antithesis documentation (https://antithesis.com/docs/llms.txt) as its
feature checklist. Each row is an Antithesis feature, where determinismo stands, and what is
next. ✅ done and tested by `zig build e2e`; 🟡 partial; ❌ missing. Update the row with the
change that moves it.

## Setup and the system under test

| Antithesis | determinismo | Status |
|---|---|---|
| Docker Compose setup | `--compose` importer: images, builds, env, service names that are no node names (a node of a derived name, the service's name its hostname and an alias every node resolves; container_name and hostname too), depends_on (a `service_healthy` dependency ready once its healthcheck passes; a `service_completed_successfully` dependency a one-shot: ended before its dependents start, never started again), ports, mem_limit, privileged, ulimits, volumes (a host directory or named volume used by several services shared as one directory, the guest's, which a node's crash leaves as a container's leaves the host's; a project's file copied into the image of the service mounting it; tests/antithesis-compat/volumes); ours, a service's fault kinds from its labels (`determinismo.faults: "+restart,+crash,-partition"`, `determinismo.no-faults: "true"`), as a Zig profile declares them | ✅ |
| Kubernetes setup | `--kubernetes <manifests directory>` (CLI, HTTP, MCP, the UI's New run): raw manifests (Helm rendered first) in a single-node K3s cluster with CoreDNS and local-path storage, no Traefik, ServiceLB or metrics-server; images fully qualified and taken from the host into the node (the guest has no network); every container, whoever made its pod (a Deployment, a bare Pod, an operator), given libvoidstar, its device, the coverage bitmaps and the SDK's output (containerd's default spec with them added as its runtime's base: det-kubespec); applied until all apply, then everything rolled out and ready (kapp's readiness) before branching; test templates in any image run in its pod (`kubectl exec`); the pods' output as events named after each pod (det-podlogs follows kubelet's logs); `examples/kubernetes`. K3s in a test program's node, or a three-node cluster: `examples/k3s`; faults as Antithesis's on Kubernetes, whose node is a pod: pod faults (paused, killed, isolated, degraded, partitioned), honouring the exclusions and sparing kube-system, while the K3s node itself (the whole cluster) is never paused, throttled or cut off, only reached by the machine-wide faults (thread pausing, clock skips, CPU modulation) | 🟡 faults on single pods (a pod frozen, killed with kubelet starting it again, cut off, its network degraded in its own namespace, or two pods partitioned from each other; the cluster's own kube-system pods are left to the node's faults, and pods holding test templates are not killed: the drivers run there) beside the K3s node's own faults; the node's process and thread pauses stop a process of its pods, never K3s, containerd or a pod's shim or sandbox (stopped, they broke the drivers' `kubectl exec`, not the system); custom resources' own readiness not awaited yet (an operator's pods count once they exist); no CrashLoopBackOff property (Antithesis's, on request): a pod's container that keeps crashing fails "no unexpected container exits", while kubelet's back-off follows our own pod kills too, so its state alone would blame healthy pods |
| Setup mode, `setup_complete` | snapshot at `setup_complete` (SDKs, composer, `setup_` template commands) | ✅ |
| Setup mode's assistant (the setup alone, its build and setup logs as they come, then a full run) | `explore --setup-only` (serve's `setup_only`, the New run form's Setup mode box): the system prepared and booted, its setup run to `setup_complete` and stopped, no timeline nor catalog judged, its events kept (the Logs Explorer shows a run without a timeline's setup as timeline 0) and its output streaming; its VM takes a CPU before a hunt's next timeline; the run's page offers Re-run setup and Launch the full run (the same request with timelines); `setup-mode` e2e check | 🟡 no editing of the configuration from the page between setups (Antithesis's Update configuration, and re-run): the files are edited where they are, then Re-run setup |
| The Antithesis environment (one vCPU, no rdrand, deterministic time) | patched KVM, branches clock, CPUID baseline; every node has `ANTITHESIS_OUTPUT_DIR` (`/run/antithesis`), Antithesis's output sink: what is written to files there becomes events (det-sinks): `.jsonl` lines as they are (an SDK's assertions, `antithesis_setup`), `.bin` bytes in base64, other files' lines as output under the node and the file; and `ANTITHESIS_FILTERED_OUTPUT_DIR` (`/run/antithesis-filtered`), the retroactive sink: its lines are left out of an exploration's events and written by a replay of the timeline | ✅ |
| Handling external dependencies | no network beyond the guest; [DEPENDENCIES.md](DEPENDENCIES.md): containers or mocks (MinIO, LocalStack, emulators, stripe-mock), names, readiness, storage, memory | ✅ |

## Faults

| Antithesis | determinismo | Status |
|---|---|---|
| Partitions (stopped, slowed, jammed; groups; asymmetric) | `partition_groups`: the runner and nodes split into 2-3 groups, stopped, slowed or jammed (held, then delivered), both ways or (half the time) one way only; single links too | ✅ |
| Clogs (a node's inbound/outbound) | `clog`: a node's inbound, outbound or both, stopped, slowed or jammed; isolate (links down) | ✅ |
| Baseline latency, restore | `network_baseline`: delay, jitter and drops (ppm) drawn per timeline, on every link that allows degradation, all run long. Network faults overlap, each link carrying the most aggressive (down, then loss, then delay); `restore` heals them all at once (logged only when some were under way). Durable disks (crash and disk faults) have theirs: `disk_baseline`, 0 to 2 ms per I/O drawn per timeline, so a sync takes time and other threads run meanwhile | ✅ |
| Node throttling, pause, kill/stop and restart | throttle, pause, restart (a kill), stop (SIGTERM, a grace period, then a kill), crash, wipe, process_kill; one at a time on a node, several nodes at once (Antithesis's overlap rule); a restarted node may rejoin at a new address (`new_address`, on for Compose projects: every hosts file follows it) | ✅ |
| Clock skips | clock_skip, forward or back; a quarter permanent, so they stack | ✅ |
| Fault settings redrawn during a run (the injector's settings, off in about a third of draws, redrawn at rollouts and intervals: Antithesis's public runs) | swarm testing: each timeline keeps fault kinds by a drawn probability (meta-swarm) and weights them (1 to 64); regimes of rate (a mean gap 100 ms to 25.6 s) and duration (scale 1 to 8) last 10 to 120 s, then are redrawn with the kinds and weights; `fault_swarm` and `fault_regime` events; `--no-swarm` for the fixed injector | ✅ |
| The test composer's command weights per rollout (`masked_for_rollout`) | the composer keeps drivers per timeline (`composer.swarm <name>`, one of a scenario's `workload` drivers at least), its load in stretches (steady, quiet, a spike), and `swarm_choice` in every SDK for a workload's own operations | ✅ |
| Fault exclusions (`antithesis.fault_exclusions`: a regular expression, Rust's syntax, over container names, or pod names on Kubernetes) | `--fault-exclusions <regex>` (CLI, serve's runs): a node whose name matches gets no fault of its own and is in no partition, isolation or outage, a matching pod is passed over by pod faults; clock skips reach every node, as Antithesis's thread pausing (the machine's) does; the syntax's part names need (literals, classes, anchors, groups, alternation, `* + ?`), anything else refused when the run is asked for (`guest/runtime/regex.zig`); e2e `fault-exclusions`, `kubernetes` | 🟡 not yet in profiles or the UI's New run |
| Faults aimed at a node (beyond Antithesis: Jepsen's nemeses target the primary) | `sdk.fault_aim(name)` from the scenario: half the injector's faults then involve that node (itself, or a link of it), each a named decision (`fault.aim`, `fault.aimed`) strategies see and replays repeat; "" stops. Workloads aim at what they find: SQL's primary (`node_names`), MongoDB's primary, Kafka's and Redpanda's transaction coordinators, the etcd, rqlite, ZooKeeper and NATS stream leaders, PD's leader (TiDB, SurrealDB). Other SDKs: `det-faults aim <node>` underneath where they run commands. The `aim` check measures it | ✅ |
| Per-node clock skew (beyond Antithesis's global skips: Jepsen's clock bumps) | `Faults.clock_skew` (off by default; `clock_skew_ms_max`, 10 s, below a system's documented maximum offset): one node's CLOCK_REALTIME ahead or behind by 1 ms to its maximum for a while (one in four strobing, Jepsen's strobe: the skew comes and goes every 10 ms to a second), its monotonic clock untouched. Each node runs in a time namespace of its own, and the guest kernel's patch 0005 gives namespaces a realtime offset changeable at any time: the vDSO, the syscalls, and absolute deadlines (clock_nanosleep, timers, timerfd, futex waits) in the node's time. The selftest's `inject` check measures it | ✅ |
| Thread pausing (theirs needs their instrumentation: it pauses at its callbacks) | at the instrumentation's callbacks too: inside determinismo, one stretch of two seconds in four (a named decision, "thread pausing"), one edge or line in 64 is a slow point with its own pause (1 to 10 ms), where every thread that reaches it waits, at most 8 times a stretch. Threads waiting together at a point run a check-then-act's checks before any of its acts: `examples/race`, the 64-thread race of "Hillel joins Antithesis". In the C SDK's trace-pc-guard callbacks (C, C++, other LLVM languages), Rust's, Zig's, Go's (`determinismo-toolexec`: a goroutine sleeps, the others run), the JVM's coverage agent (lines and after each conditional branch), Python's `coverage_start` (lines and branches), .NET's `Coverage.Point` (each statement, through `determinismo-dotnet-instrument`) and Node.js's `coverageStart` (its breakable positions, through the inspector: V8 calls nothing at a block, so a helper thread sets the stretch's slow points as breakpoints in the main thread and every worker under coverage, and resumes each after its pause; a CommonJS file's points set before a worker runs it, an ES module's once a thread parsed it); and libvoidstar's callbacks, for code built for Antithesis (its Go instrumentor's, trace-pc-guard's: the Raft POC). Each is checked on `examples/race` in its language. What a node's code pauses at is its coverage set (`.coverage` on the node: include and exclude prefixes, every SDK's). Without instrumentation, `thread_pause`: one thread stopped (ptrace) wherever it is when the injector runs (at a tick), the rest of its process running; process_pause too | 🟡 an ES module's code run at its load, before its slow points are set, is not paused |
| Interleavings (beyond Antithesis) | `interleave`: for a while, one in a few of the guest scheduler's choices among a node's threads is drawn (a woken thread runs before its waker goes on, a tick preempts, a random runnable thread runs next; guest kernel patch 0006, the module seeded from the platform at each fault). On by default (`Faults.interleave`); the selftest's `interleave` check measures it | ✅ |
| CPU modulation | on by default (`--no-cpu-modulation`, MCP and HTTP `cpu_modulation: false`, turn it off): branches run up to twice as slow for stretches of 10-200 ms of virtual time, each speed a decision (a strategy can steer it, tapes replay it), so timer interrupts and preemption land at other points | 🟡 the clock only: Antithesis also changes particular instructions' relative speed, which virtual time made of retired branches (the one count the hardware keeps deterministic) cannot express |
| Disk faults (restarts that keep durably synced changes, or lose all) | `crash` (an ext4 disk per node, shut down without flushing: what was synced survives) and `wipe` (fresh from the image); `--faults +crash`. Antithesis's "customised durability behavior" (theirs per directory, through their engineers): a node's `writeback_s`, its disk synced that often as a host's flusher would, so a crash loses only the last window's unsynced writes (RabbitMQ's brokers: 30 s) | ✅ |
| Partial persistence at a power loss (beyond Antithesis) | half of a node's drawn power losses (crash, durable_crash, outage) persist part of what it had not synced, as a host's flusher may have written it back before the power went (LazyFS's torn-seq and torn-op, Ramos et al. VLDB 2024): a file in three of its layer; of each, a few 4 KiB pages over allocated blocks in any order, and its new data (delayed or unwritten extents, FIEMAP) as an ascending run from the start of one of its new ranges, as the flusher writes it (no hole before a kept page of a fresh file); then half the time the journal committed (appended pages survive too), else only overwrites in place. A decision, replayed; `node_crash_partial` events say what (files, pages, commit). `Faults.partial_persistence = false` keeps Antithesis's exact loss; `sdk.fault(.{ .kind = "crash", .partial = true, .partial_commit = true })` asks for one. The selftest's disk check: of 30 fresh files' unsynced pages, some kept (each file's a prefix) and in some timelines some lost | ✅ |
| Correlated power losses (beyond Antithesis) | `outage`: several nodes lose power at the same moment, all of those that allow crashes half the time (a datacenter), else a random group of two or more (a rack); all frozen first, each keeps what it synced, all start again at its end. Jepsen's kill of a majority or of all: what loses writes acknowledged before a sync (Galera's recommended settings, Kafka's), which one node's crash never does. For nodes that allow restarts but not power losses (YugabyteDB's, whose log is not synced by default), a kill of several at once (Jepsen's YugabyteDB #2125 came from every master killed together). `sdk.fault(.{ .kind = "outage", .nodes = ..., .power = false })` asks for one | ✅ |
| A cap on nodes down at once (beyond Antithesis: Jepsen's nemeses take a minority) | a scenario's `nodes_down_max`: at most that many nodes killed, powered off, stopped or wiped at once, outages counted; a fault past it skipped (`fault_skipped NodesDownMax`). The nodes' own faults overlap otherwise (one node's restart beside another's power loss). For a claim that covers a minority's failures (Iggy's `replicated` durability, a 2n+1 cluster surviving n). The `nodes-down` check measures it | ✅ |
| Disk I/O faults (beyond Antithesis) | `disk`: the node's disk through device-mapper, its table swapped for a while: every I/O failing, writes failing, writes acknowledged and never stored (gone at the next crash, synced or not, or sooner once the kernel drops the page from its cache: a read then returns what the disk held), corrupted reads, or slow I/O (dm-flakey, dm-delay). An exit meanwhile is expected; at the end a node that exited or whose filesystem went read-only starts again. `--faults +disk`, or `sdk.fault(.{ .kind = "disk", .failure = "lost_writes", ... })` | ✅ |
| Durability points (beyond Antithesis) | the guest module makes a node's fsyncs, fdatasyncs, msyncs and sync writes decisions while a fault lasts: `sync_stall` (on by default) holds the ones picked for a drawn time, up to a second, while the node's other threads run; `durable_crash` (with `+crash`) crashes the node at one, just before its data reaches the disk or just after. Any language or store: a guest kernel hook in `vfs_fsync_range` (guest/kernel/patches/0008) | ✅ |
| Crash points (beyond Antithesis: CrashTuner, SOSP 2019) | the JVM coverage agent makes a node's state transitions (stores of its own enum constants) and its stores to fields named as the node's view of the cluster (`leader`, `epoch`, `term`, `session`, `member`...) crash points: one two-second stretch in eight (a named decision, `crash points`; `DETERMINISMO_CRASH_POINTS`), one point in four, a thread there asking the injector to crash its node now (`det-faults crash-point`) and waiting for it, before the store or just after; granted as one of the node's crash faults the swarm keeps (a kill or a power loss, `why: crash_point`), refused at once in quiet periods (`/opt/determinismo/crash-points`). Points a program marks itself: `sdk.crash_point(name)` (Zig), `crash_point(name)` (Python), `CrashPoint(name)` (Go), `det_crash_point(name)` (C, C++), `crash_point(name)` (Rust), `Lifecycle.CrashPoint(name)` (.NET), `crashPoint(name)` (JavaScript) and `det_crash_point` (libdeterminismo: Clojure, jank). The `crash-points` check measures both | 🟡 states found by themselves on the JVM only; elsewhere marked by hand, in every SDK |
| Errors a system call may return (beyond Antithesis's faults; its "make rare events common" for code we cannot edit) | `Faults.signals`: a signal the process catches (SIGCHLD, SIGURG, SIGWINCH, SIGPIPE) at a drawn moment, the kernel making the EINTRs where its handler does not restart; `Faults.syscall_errors`: the kernel's fail_function on one of a node's system calls, one call in a few, with an error its manual allows whatever the descriptor (EMFILE, ENFILE, EAGAIN, ENOMEM, EIO, ENOSPC); `Faults.file_errors`: a guest kernel hook at every read and write of a regular file (guest/kernel/patches/0010) failing those of the node's disk with ENOSPC, EDQUOT or EIO. All off by default, a workload's choice | ✅ |
| Custom faults | `Faults.custom`: commands in a node the injector runs at random times (they can draw randomness); quiet periods hold them too. And any fault on request from a scenario: `sdk.fault(...)` (Zig, C, Python, JVM, Clojure) or `det-faults inject '<json>'` (any language): applied, logged and undone like a drawn one, in quiet periods too, and on a node `--fault-exclusions` leaves out (the scenario named it) | ✅ |
| Pausing faults (quiet periods) | `$DETERMINISMO_STOP_FAULTS <seconds>` (also `$ANTITHESIS_STOP_FAULTS`) in every node, command and imported Kubernetes container: the fault under way ends, no drawn fault but clock skips starts, overlapping requests merge to the longest; faults only in the driver phase. A fault a scenario asks for (`sdk.fault`, `det-faults inject`) still starts: a scenario quiets the drawn ones to inject its own alone (examples/datomic's takeover) | ✅ |
